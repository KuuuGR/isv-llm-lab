# Decision Log

Each entry: what was decided, why, and any later revision. Newest last.
Format: `DATE · D-### · decision`.

---

## D-001 · 2026-08-31 · Prefer the active JS morphology engine over the legacy dictionary engine

`@interslavic/utils@3.4.0` (used by the dictionary app) is deprecated and
superseded by `@interslavic/morphology@0.1.2` in the `medzuslovjansky/js-utils`
monorepo. Use the new packages for any morphology work; treat the legacy package
as reference only.

## D-002 · 2026-08-31 · Snapshot generated dictionary data, not the app or the spreadsheet

`basic.json` (generated artifact, 19,101 rows) is the reproducible lexical
reference. Do not vendor the dictionary app, do not depend on the live Google
Spreadsheet, do not rebuild the data ourselves.

## D-003 · 2026-08-31 · Rust morphology is "use later", not "use now"

The Rust crate is a credible deterministic backend (MIT OR Apache-2.0, parity
harness vs JS, `lemma + features → form` API). For the baseline evaluation the
JS engine (plus its full-form dumper) is the lower-integration-cost path. Revisit
after Experiment 001.

## D-004 · 2026-08-31 · Evaluation must distinguish "not a headword" from "morphologically unjustified"

The important metric is the second one. An inflected form is VALID if a known
Interslavic lemma produces it via the morphology engine — never classify as
unknown merely because it is not a dictionary headword. (See DESIGN.md § Metrics.)

## D-005 · 2026-08-31 · Do not trust POS heuristics in evaluation

`detectPos`/`guess_gender` are crude (e.g. `morem` → "masculine"). Validity
checks must be lemma-driven, not surface-driven.

## D-006 · 2026-08-31 · Vocative handling depends on the engine

The JS engine emits vocative cells for feminine consonant stems and neuters
(e.g. `kosti`); the Rust engine returns `None` there (per Steen's prose). The
evaluation must document which engine's surface lexicon is the reference and be
consistent about it. For the baseline, prefer the JS-generated full-form lexicon.

## D-007 · 2026-08-31 · Preserve raw model outputs; never overwrite

Every experiment result is stored under `experiments/<exp>/outputs/<run_id>/`
with `run_id = date + provider + model + version`. Different model versions are
different experimental conditions.

## D-008 · 2026-08-31 · The task's `more → morem` example is not reproducible as stated

The dictionary headword for "sea" is `morje`; `more` inflects as an n-stem
neuter (ins.sg. `morętem`/`morętom`). `morem` is not generated by either
engine. Do not use this pair as a test case without correction.

## D-009 · 2026-08-31 · Dictionary data license is unresolved — no redistribution yet

The app code is MIT, but the dictionary *data* provenance (Steen's dictionary,
Google Spreadsheet) has no stated license. Snapshot the data locally for
internal reproducibility; do not publish derived datasets until resolved.

## D-010 · 2026-08-31 · The full-form lexicon is practical: generate it from `basic.json` via the published morphology package

Driving the *published* `@interslavic/morphology` `inflect()` directly with
each dictionary row (`{form, xpos, addition}`) works well: irregular hints in
the `addition` column (e.g. `oko (oka/očese; pl. oči)`, `pisati (piše)`) are
honored. Generated the whole dictionary in ~86 s → **320,824 lexicon entries**
(headwords + full paradigms). Two formats must be pre-processed before
inflection: comma-separated variant lemmas (`den, denj`) are split per piece,
and numeric metadata annotations (`(+2)`, `(+6)`) in the addition column are
filtered out (they are not morphology hints). The js-utils `tools/dump` dumper
was NOT reused because it is coupled to the monorepo's internal fixtures.

## D-011 · 2026-08-31 · Morphology lives behind a narrow stdio subprocess interface

The Node backend (`src/morphology_backend/backend.mjs`, pinned deps, committed
lockfile) exposes exactly two operations over line-delimited JSON: `inflect`
(batch lemma→paradigm) and `translit` (Cyrillic→ISV Latin). Python orchestrates
everything else. Never reimplement morphology in Python. (Fixed a truncation
bug: `process.exit()` on stdin close cut off unflushed stdout.)

## D-012 · 2026-08-31 · Bucket B is a bounded live fallback, not the primary mechanism

Bucket A uses the precomputed full-form lexicon (headwords + paradigms), which
is what makes "exact match" meaningful for inflected text. Bucket B rescues
forms missing from the lexicon by re-inflecting candidate dictionary lemmas
(shared 3–4 char prefix, ≤150 candidates, dictionary POS passed as a hint).
With a complete lexicon B rarely fires; it is the safety net for lexicon gaps
and the DESIGN.md §5 procedure, exercised by a dedicated test.

## D-013 · 2026-08-31 · Conservative tokenizer: stdlib `re`, lexical tokens exclude numbers/punctuation

Paragraph = blank-line block; sentence = split after `. ! ? …` + whitespace
(quotes closing after sentence-final punctuation are not split — documented
limitation). Hyphenated/apostrophe compounds (`po-mojemu`) stay single tokens.
`is_lexical` = contains a Unicode letter; numbers and punctuation are excluded
from every coverage denominator.

## D-014 · 2026-08-31 · Normalization is conservative: NFC+lowercase primary, etymological folding secondary

Primary lookup key: NFC + lowercase (diacritics kept). Secondary key folds
*etymological-only* characters (å ę ų ȯ ė ć đ ď ĺ ľ ń ŕ ś ť ź) to base
letters, so `ženoju` matches `ženojų`; standard letters (č š ž ě) are NOT
folded. Cyrillic tokens are transliterated to ISV Latin before lookup.
Surface forms are never modified; `folded_match` is flagged in results.

## D-015 · 2026-08-31 · Metrics reconciliation: `morphologically_valid_coverage = (A + B) / lexical_tokens`

The task instruction defines the formula as (exact + valid) over lexical
tokens; DESIGN.md §6 wording ("tokens in bucket B / total_tokens" with the
parenthetical "headword-or-justified") is reconciled to the (A+B) reading.
The denominator policy is stated in every report and in DESIGN.md §6.

## D-016 · 2026-08-31 · Dictionary snapshot and lexicon artifacts stay local and gitignored

`scripts/fetch_dictionary.py` snapshots `basic.json` + writes
`data/dictionary/manifest.json` (url, retrieved_at, sha256, size, row_count,
schema, license_status=UNRESOLVED). `scripts/generate_lexicon.py` writes the
TSV lexicon + `lexicon.manifest.json`. All of it is gitignored (only
`data/dictionary/README.md` is committed). The manifest content is embedded in
every `isv-eval` report for reproducibility.

## D-017 · 2026-08-31 · Batch the bucket-B morphological fallback

Full-story evaluation exposed a runtime bottleneck: the fallback spawned one
Node subprocess per unresolved token. The fallback now collects all tokens
needing bucket B, deduplicates their candidate lemmas, and sends one
`inflect` call per chunk (2000 lemmas). Classification results are identical
(31 tests unchanged); full-story runs dropped from minutes to seconds.
Methodology is unchanged — only the transport.

## D-018 · 2026-08-31 · Externally generated outputs get explicit `unknown` metadata, never inferred values

Model versions, generation dates, prompts and (where applicable) providers
for the seven baseline outputs are not known; `meta.json` records `unknown`
for every missing field and `prompt_status = unknown` (no output can be
confirmed to have used `prompt_template.txt`). Provision timestamps come from
raw file mtimes. Nothing is inferred from filenames or assumptions.

## D-019 · 2026-08-31 · The custom GPT condition stays separate from ordinary ChatGPT

"GPTs — Interslavic — Medžuslovjansky Language Teacher" is its own condition
(`model = gpt-isvt`, `condition_type = specialized_custom_gpt`, separate run
directory and row in the comparison table). Its internal system instructions
are not available and are explicitly recorded as such; the run's `prompt.txt`
is the standard template plus a documented note, not the unseen instructions.

## D-020 · 2026-08-31 · Source corpus and translation prompt are separated; raw byte size is not a translation-length metric

For future controlled experiments, `source.txt` contains **only** the actual
Polish story and `prompt.txt` contains the translation instructions + source
text (a concept Experiment 001's supplied `op-pl.txt` violated by embedding an
instruction line and markdown fence). Consequently, raw file size is NOT a
valid comparison of translation length or quality in Experiment 001 — sizes
are recorded for input integrity only, and the previous report's size
observation is clarified accordingly. No new length metrics are implemented in
this task; they are recorded as future ideas in ROADMAP.
