# Paper 1 — Targeted replication protocol (EXP-003R)

**Status:** DESIGN ONLY — not executed.  
**Date:** 2026-09-20  
**Predecessor audit:** [`paper1-replication-audit.md`](paper1-replication-audit.md)  
**Mechanism:** generation-time resource guidance (EXP-003-like).  
**Not in scope:** EXP-002 post-hoc revision; corpus priming (Phase 2B); Grammar Aggregator validation; evaluator redesign.

**Working experiment id (proposed):** `exp003r`  
**Preferred cell count:** 2 configurations × 4 conditions × 3 independent repeats = **24 runs**.  
**Optional expansion:** +1 configuration → **36 runs** (same conditions/repeats).

Replication may begin only after the decision gate in §16 is satisfied.

---

## 1. Research question

> For a fixed Polish source and a fixed model configuration, does supplying a
> deterministic, resource-derived Interslavic guidance block at **generation
> time** change the measured translation outcomes (canonical coverage and,
> separately, broader resource-supported coverage; plus orthography as a
> separate measure) relative to **direct generation** with the same
> instructions and source?

Narrower estimands (pre-declared; §10):

1. **Lexical assistance effect:** one canonical candidate vs Direct (B − A).
2. **Multiple-alternatives effect:** multiple resource-supported candidates
   vs one candidate (C − B), and vs Direct (C − A).
3. **Grammar-guidance add-on:** lexical alternatives **plus** grammar
   annotations vs lexical alternatives alone (D − C), and vs Direct (D − A).

**Out of scope for this protocol:** claims about corpus priming, Grammar
Aggregator fact quality, human preference as evaluator validation, or
post-hoc dictionary revision (EXP-002).

## 2. Experimental design

### 2.1 Factorial structure

| Factor | Levels | Count |
|---|---|---:|
| Configuration | Config-1, Config-2 (§3) | 2 |
| Condition | A, B, C, D (§2.2) | 4 |
| Independent repeat | r01, r02, r03 (§7) | 3 |
| **Total planned primary runs** | | **24** |

Optional third configuration: same A–D × r01–r03 → **+12 = 36** total.

### 2.2 Conditions — what the model sees

All conditions share:

- the same frozen Polish source (§4);
- the same shared instruction skeleton (§6);
- the same configuration settings within a config (§3).

They differ **only** by the presence/content of the guidance block.

| Cond | Name | Exact information presented beyond shared skeleton + source |
|---|---|---|
| **A** | Direct / no assistance | Nothing. No lexical scaffold. No grammar scaffold. |
| **B** | One canonical lexical candidate | Shared scaffold intro (lexical-only) + token-aligned scaffold where each mapped Polish surface shows **exactly one** ISV candidate (the first after deterministic ordering). Names: keep-as-is. Unmapped: `[?]`. |
| **C** | Multiple resource-supported lexical alternatives | Shared scaffold intro **plus** the alternatives bullet + token-aligned scaffold showing **all** ordered candidates for that token (comma-separated). Same names/`[?]` rules. **No** grammar parentheticals. |
| **D** | Lexical assistance + grammar guidance | Shared scaffold intro **plus** alternatives bullet **plus** grammar bullet + token-aligned scaffold showing the **same candidate list as C**, with optional parenthetical grammar notes (POS; for verbs, up to 3 example paradigm forms where lexicon-backed). |

### 2.3 Intervention isolation (must be made true by freezing)

These isolations are **requirements**, not assumptions. They hold only if
the frozen scaffold build obeys them:

| Pair | Required isolation | What must be frozen to make it true |
|---|---|---|
| **C vs B** | Differ **only** in number/display of lexical alternatives (and the one extra intro bullet about choosing among alternatives). | Same underlying `scaffold.json` candidate lists; B renders `candidates[0]` only; C renders the full ordered list; **no** grammar annotations in either render; same source; same shared rules; same config. |
| **D vs C** | Differ **only** by grammar guidance (intro grammar bullet + parenthetical annotations on lines). | Same candidate lists and order as C; D adds annotations generated by the frozen grammar procedure only; **no** new lexical candidates in D that are absent from C; same source/config. |
| **B vs A** | Differ **only** by presence of the B scaffold block (+ shared lexical intro). | Identical template and source; A’s `{SCAFFOLD_BLOCK}` is empty. |
| **Across repeats** | Guidance content identical | Scaffold files and prompt bodies for a given (config × condition) are **byte-identical** across r01–r03; only run metadata / session identity changes. |

**Known residual confound (document, do not “fix”):** B/C/D prompts are
longer than A. Prompt length is inseparable from supplying guidance in this
design; interpret contrasts as “resource-guided generation package vs
direct,” not as length-matched controls.

**Known D semantics (document):** D is **not** a grammar-only arm. It is
**C + grammar annotations**. A pure grammar-only arm (e.g. B + grammar
without multi-alternative lists) is **out of scope** for this 24-run
protocol unless a later amendment adds a fifth condition.

## 3. Model / configuration selection

### 3.1 Selection criteria (reproducibility — not “best model”)

Select configurations that:

1. are **currently available** to the operator under a named product path;
2. historically completed **full-story** EXP-003 outputs without truncation
   / echo / service-error failure modes (Bielik excluded for that reason);
3. can ingest the **full** A–D prompts (including the longest D scaffold);
4. allow the operator to record a **clear model/version/thinking-mode**
   identifier;
5. provide **continuity with EXP-003’s two quantitatively usable lineages**
   where possible (OpenAI ChatGPT-family; Anthropic Claude-family).

Do **not** select by coverage rank, human preference, or Phase 2B priming Δ.

### 3.2 Recommended primary configurations (2)

| Slot | Recommended configuration | Continuity basis | Identifier to freeze before run |
|---|---|---|---|
| **Config-1** | OpenAI **ChatGPT** product path matching EXP-003’s usable lineage: historically recorded as **GPT-5.6 Luna, thinking OFF** | EXP-003 ChatGPT A–D complete | Exact product label + model/build string + thinking mode as shown in the UI/API **on freeze day** (write into `configs.json`) |
| **Config-2** | Anthropic **Claude** product path matching EXP-003’s usable lineage: historically recorded as **Claude Sonnet 5 — Medium (default)** | EXP-003 Claude A–D complete | Exact product label + model/build string + thinking/effort setting **on freeze day** |

**Bielik (or similar unstable chatbots):** not recommended for the primary
24. Optional third configuration only if integrity gates (§8) are expected
to pass.

### 3.3 Substitution rule

If the historical EXP-003 snapshot is **no longer offered**:

1. Choose the closest currently offered successor in the **same provider
   family** that still meets §3.1.
2. Record in the run manifest:  
   `historical_reference`, `substituted_configuration`, `substitution_reason`,
   `not_identical_to_exp003: true`.
3. Do **not** label the new configuration with the old EXP-003 version
   string.

### 3.4 Decoding / interface settings (freeze)

For each configuration, freeze and record:

- product path / custom GPT name (if any);
- model version / build string (as displayed);
- thinking / reasoning mode (ON/OFF/level);
- temperature / top-p / seed **if** the interface exposes them;
- if the interface does **not** expose them: record `vendor_default` /
  `unknown` — do **not** invent seeds.

Same frozen settings for all 12 runs of that configuration (4×3).

## 5. Resource intervention construction

### 5.1 Generator and provenance discipline

- Build with the existing deterministic pipeline:  
  `scripts/build_exp003_scaffold.py` (EXP-003 DESIGN §6–§7).
- **No LLM calls** inside scaffold construction.
- **No opportunistic editing** of candidates after seeing any model output.
- Freeze, then hash: dictionary / lexicon / morphology pins, curation
  tables, `scaffold.json`, and rendered `scaffold_{B,C,D}.txt`.
- Preferred freeze strategy for continuity: rebuild under **pinned**
  resource versions recorded in the replication manifest; if the rebuild
  is byte-identical to the historical EXP-003 scaffold blocks, record that;
  if not, record the new hashes and treat this as a **resource-pinned
  replication**, not a claim of identical historical bytes.

Committed curation inputs (must not be silently edited mid-study):

- `experiments/exp003-scaffold/curation/op-pl/multiword.tsv`
- `experiments/exp003-scaffold/curation/op-pl/names.tsv`
- `experiments/exp003-scaffold/curation/op-pl/residual.tsv`

### 5.2 Condition B — one canonical lexical candidate

**Operational “canonical” (this protocol):** the first candidate after the
generator’s deterministic sort for that Polish token, drawn from the
alignment pipeline:

1. multiword table →  
2. exact `basic.json` Polish-gloss reverse-index hit →  
3. dictionary-verified lemma recovery (only if re-lookup succeeds) →  
4. proper-name pass-through →  
5. curated residual table →  
6. else `[?]`.

**Ordering key (existing generator):** dictionary `type` ascending, then
alternative-attestation count descending, then orthographic-variant index,
then headword lexicographic order. The first surface after this sort is
B’s single displayed candidate.

**Display:** one line per Polish lexical token, e.g.  
`Dziś           → [dnėś]`  
Names: `Name → [Name]  (proper name — keep as-is)`.  
Unmapped: `→ [?]`.  
Curated/multiword lines may carry the `‡` provenance marker (existing
renderer).

**Not allowed in B:** multiple alternatives; grammar parentheticals.

### 5.3 Condition C — multiple resource-supported alternatives

| Rule | Specification |
|---|---|
| Maximum number | **No artificial cap** — emit **all** candidates produced for that token after deduplication and ordering (same list B draws its first element from). |
| Selection | Same pipeline as B; list = full ordered `isv_candidates`. |
| Admissible resource tiers for **creating** Polish→ISV mappings | Canonical dictionary reverse index; verified lemma recovery; committed per-story curation; names. Alternative resources (`isv.dic`, frequency lists) may **annotate** / tie-break but must **not** invent Polish→ISV mappings the dictionary/curation do not support (EXP-003 DESIGN §7). |
| Conflicting variants | Allowed if resources list multiple headwords/variants; model chooses by context. Orthographic variants of one headword may appear as separate list entries when the generator emits them. |
| Provenance display | Human-readable legend in the scaffold footer (canonical dictionary / curation `‡`); full provenance remains in `scaffold.json` (not necessarily pasted into the prompt). |
| Intro difference vs B | Add the alternatives instruction bullet (§6). |

**Not allowed in C:** grammar parentheticals; post-hoc addition/removal of
candidates to chase a desired coverage score.

### 5.4 Condition D — C plus grammar guidance

| Rule | Specification |
|---|---|
| Lexical content | **Identical candidate lists and order to C** |
| Admissible grammar information | Dictionary POS; verb aspect encoded in dictionary xpos where present; up to **3** lexicon-backed example paradigm forms for verbs (infinitive; 1sg present; past m.sg) when `lexicon.tsv` supplies them |
| Domains **not** allowed | Polish-side morphological analysis; invented tense/aspect mapping from Polish; free-form grammar essays; Grammar Aggregator facts not already in the frozen EXP-003 generator path |
| Presentation | Parenthetical after the candidate list, e.g. `(v.; e.g. form1, form2, form3)` or `(adj.)`; omit parenthesis when no reliable annotation exists |
| Text budget | Per-token short annotations only (generator-bounded examples ≤3); no extra prose paragraphs beyond the shared intro grammar bullet |
| Fixed across repeats? | **Yes** — same `scaffold_D.txt` bytes for r01–r03 |

### 5.5 Pre-commitment (anti-fishing)

Before any Config×Condition×Repeat generation:

1. Build scaffolds once.
2. Record SHA-256 of `scaffold.json`, `scaffold_B.txt`, `scaffold_C.txt`,
   `scaffold_D.txt`.
3. Package all 8 prompt bodies for the two configs (A–D each) **or** one
   shared A–D prompt set if only the header model name differs — either way,
   freeze hashes.
4. Enter hashes into the run manifest.
5. Only then open model sessions.

Changing a candidate because a pilot peek looked bad is a **protocol
violation**.

## 6. Prompt protocol

Reuse the EXP-003 packaging structure
(`experiments/exp003-scaffold/prompt_template.txt` +
`scripts/package_exp003_prompts.py` scaffold intros), with experiment id
relabeled to `exp003r` in headers once packaging is frozen.

### 6.1 Shared skeleton (all conditions)

**Instruction / rules text (fixed):**

- Translate the Polish story into Interslavic (Medžuslovjansky).
- Translate the complete document (title, headings, paragraphs) in order.
- Preserve paragraph breaks, character names, quoted dialogue.
- Produce natural, idiomatic Interslavic (coherent story, not word-for-word).
- Return **only** the Interslavic translation — no explanations, comments,
  notes, or alternative versions.

**Source text:** identical frozen story in a fenced block under  
`## Source text (Polish)`.

**Output constraints:**  
`## Output` — return the complete Interslavic translation and nothing else.

**Header metadata** (may name the configuration and condition):  
experiment id, target model display name, condition label.

### 6.2 Condition-specific blocks

| Cond | `{SCAFFOLD_BLOCK}` contents |
|---|---|
| A | empty string |
| B | `_SCAFFOLD_INTRO_COMMON` + `scaffold_B.txt` |
| C | `_SCAFFOLD_INTRO_COMMON` + `_SCAFFOLD_INTRO_ALTERNATIVES` + `scaffold_C.txt` |
| D | `_SCAFFOLD_INTRO_COMMON` + `_SCAFFOLD_INTRO_ALTERNATIVES` + `_SCAFFOLD_INTRO_GRAMMAR` + `scaffold_D.txt` |

Canonical intro wording (must match frozen packaging; copied from the
EXP-003 packager):

**Common (B/C/D):** lexical scaffold is dictionary guidance, not a finished
translation; free word order / constructions; inflect candidates; `[?]` =
no mapping; proper names keep-as-is; do not copy mechanically.

**Alternatives (C/D only):** where several alternatives are listed, choose
the one that best fits; all listed alternatives are resource-supported.

**Grammar (D only):** parenthesised annotations are POS / aspect / example
forms — hints, not mandates; model remains responsible for final surfaces
and agreement.

### 6.3 What may differ between conditions

**Allowed differences:** only the `{SCAFFOLD_BLOCK}` content defined above
(and the condition name/label in the header).

**Forbidden differences:** different source bytes; different rule lists;
different output contracts; condition-specific temperature; injecting
corpus-priming passages; injecting Grammar Aggregator packages; editing
scaffolds between conditions except via the frozen B/C/D renderers.

### 6.4 Byte reproducibility

After variable insertion (`EXPERIMENT_ID`, `CONDITION_*`, `MODEL_NAME`,
`STORY`, `SCAFFOLD_BLOCK`), each prompt file must be reproducible
byte-for-byte. Record `prompt_text_sha256` per packaged file before
execution. Repeats of the same (config × condition) use the **same**
prompt hash.

## 7. Replicates

| Item | Definition |
|---|---|
| Repeat | An **independent model call / chat session** that receives the frozen prompt for that (configuration × condition) and returns a new raw output |
| Count | **r01, r02, r03** for every cell |
| Independence | New session (or equivalent isolation); do not continue from a previous repeat’s context; do not paste prior outputs into later prompts |
| Seeding | Use an explicit seed **only if** the service exposes one. If not, record `seed: not_supported` / `vendor_default`. **Do not invent** deterministic seeds |
| Prompt identity | Same prompt hash across the three repeats of a cell |
| Output identity | Each repeat stores its own immutable output file + `meta.json` |

### 7.1 Required run metadata (minimum)

Record for every run:

- `run_id` (see §7.2);
- configuration id + frozen model/version/thinking mode;
- condition `A|B|C|D`;
- replicate `r01|r02|r03`;
- generation timestamp (UTC);
- interface path (web UI / API);
- decoding fields (temperature/top_p/seed or `vendor_default`);
- `source_sha256`, `prompt_text_sha256`, `scaffold_sha256` (null for A);
- resource pins (dictionary/lexicon/morphology commits or file hashes);
- evaluator package version / git commit used at evaluate time;
- operator notes (non-content: e.g. “session restarted after browser crash”
  — never silent prompt edits).

### 7.2 Run id pattern (compatible with project practice)

```text
<date>__<provider>__<model>__<model_version>__<condition>__<replicate>
```

Example shape:  
`2026-10-01__openai__chatgpt__gpt-5.6-luna-thinking-off__b__r02`

## 8. Validity and exclusions

Define **before** execution. Do not exclude a complete translation because
its coverage is low or high.

### 8.1 Valid run (enters primary analysis)

All of the following:

1. Status `complete` after intake inspection.
2. Output is an Interslavic **translation attempt** of the story (not a
   prompt echo, not a service error page, not an empty body).
3. Structural completeness gate (same spirit as EXP-003 intake): title /
   section progression present; story reaches a recognizable end marker
   (`KONIEC` / `KONEC` / `KONĖC` or equivalent complete ending); not truncated
   mid-act mid-sentence as the final state.
4. No required post-editing of model bytes (raw output stored
   byte-for-byte).
5. Metadata complete; hashes match the frozen plan for that cell.

### 8.2 Failure classes (excluded from primary paired means; preserved)

| Class | Examples | Primary analysis | Preservation |
|---|---|---|---|
| Service failure | HTTP/UI error page, “temporary problems” | Exclude | Keep raw + status |
| Timeout | Session dies mid-generation with partial text only | Exclude | Keep |
| Truncation | Ends mid-story / mid-word without completion | Exclude | Keep |
| Refusal | Model declines to translate | Exclude | Keep |
| Malformed output | Only metadata/commentary; no story body | Exclude | Keep |
| Missing translation | Empty file / whitespace only | Exclude | Keep |
| Prompt echo | Returns instructions/scaffold instead of translation | Exclude | Keep |
| Evaluator failure | Tool crash / env break (not a model failure) | Do not analyze until evaluator rerun on same bytes | Keep output; fix tooling; re-evaluate **same** file |

### 8.3 Retry / replacement rule

- Infrastructure failures (service error, timeout, browser crash **before**
  a complete output exists) may be **retried**.
- Each attempt gets a new audit entry; failed attempts remain on disk.
- A replacement that will occupy the planned cell must be labeled  
  `replacement_of: <failed_attempt_id>` and must use the **same frozen
  prompt hash**.
- **No** replacement solely because coverage disliked.
- Cap: document a maximum of **2 infrastructure retries** per cell; if still
  failing, mark cell `failed` and proceed (do not silently swap configs).

### 8.4 Partial outputs

Never “complete” a truncated output by hand. Never splice multiple attempts
into one file.

## 9. Evaluation

### 9.1 Evaluator

- Use the existing project evaluator (`isv-eval`) **unmodified**.
- Freeze evaluator git commit / package version in the manifest before the
  first evaluation.
- Apply the established two-tier reporting (Task 008 / RESOURCE_POLICY).

### 9.2 Metrics to report (side by side — never collapsed)

**Primary (coverage):**

- `canonical_coverage` (and supporting token counts);
- `broader_resource_supported_coverage` (if the established pipeline emits it
  for these runs — it should).

**Separate orthography measure (if available via existing audit tooling):**

- character-level outside-inventory rates (Task 015 style), including
  non-name refinements when the existing scripts provide them.

**Optional secondary (existing EXP-003 comparison tooling):**

- unresolved rate;
- token-aligned A/B/C transitions vs the same-config Direct mean or vs paired
  A replicate (document choice in analysis note);
- candidate adoption / invented-form diagnostics.

### 9.3 Metric meaning (restated)

**Canonical coverage is resource-supported coverage under the canonical
dictionary/morphology path — not “percentage of correct Interslavic.”**

Broader coverage is a separate attestation tier. Orthography is a separate
character-inventory sanity layer. Do **not** merge these into one quality
score.

## 10. Primary contrasts

All contrasts are **within configuration**, in **percentage points** of the
chosen coverage metric (canonical primary; broader reported parallel).

| Contrast | Estimand | Scientific question |
|---|---|---|
| **B − A** | mean(B) − mean(A) over 3 repeats | Does **one-candidate lexical assistance** change outcomes vs Direct? |
| **C − A** | mean(C) − mean(A) | Does **multi-alternative lexical assistance** change outcomes vs Direct? |
| **C − B** | mean(C) − mean(B) | What is the **incremental effect of multiple supported alternatives** beyond one candidate? |
| **D − A** | mean(D) − mean(A) | Does the **full C+grammar package** change outcomes vs Direct? |
| **D − C** | mean(D) − mean(C) | What is the **incremental effect of grammar guidance** beyond multi-alternative lexical assistance? |

**Do not** designate an overall winner across configs or conditions.

Conceptual grouping:

- Lexical assistance: B−A, C−A, C−B  
- Grammar add-on (given lexical alternatives): D−C (and D−A as package vs Direct)

## 12. Contamination / leakage controls

| Risk | Control |
|---|---|
| Operator sees outputs before building interventions | Scaffold build + prompt freeze **before** any generation (§5.5) |
| Candidates chosen to improve a particular model | Forbidden; generator is deterministic; no hand-picking after peeks |
| Changing scaffolds between repeats | Same scaffold/prompt hashes for r01–r03 |
| Using previous outputs to improve later prompts | Forbidden (no few-shot from EXP-003R or historical EXP-002/003 outputs) |
| Corpus-priming material | Forbidden in this protocol (belongs to Phase 2B, not EXP-003R) |
| Grammar Aggregator facts from experimental outputs | Forbidden; D uses only the frozen EXP-003 grammar annotation path |
| Independence from historical EXP-002/003 **outputs** | Do not paste historical translations into prompts; historical runs remain archival. Reusing the **frozen source + curation + generator code** is allowed and intended |
| Evaluator fishing | Freeze evaluator commit before evaluation; do not retune `isv-eval` mid-study |

## 13. Human evaluation

**Not repeated in this protocol.**

**Reason:** the targeted scientific gap identified by the audit is the lack of
**independent repeated automated runs** under frozen configs for objective
coverage (and separate orthography). The EXP-003 human forced-choice test
was exploratory (single participant) and is not required to estimate the
§10 contrasts.

If a later amendment adds human preference:

- treat it as an **exploratory secondary** protocol with its own DESIGN;
- do **not** present it as validation of `isv-eval`;
- do not delay the 24 automated runs on that account.

## 14. Power / scope language

This study is a **compact targeted replication** (24 primary runs; optional
36).

It is intended to:

- improve **repeatability** relative to historical `n = 1` cells;
- estimate **observed treatment contrasts** (§10) under frozen pins;
- reveal whether B/C/D patterns are stable across three draws per cell.

It is **not**:

- a formal power-analyzed universal estimate across models, stories, or
  languages;
- a claim that two configurations represent all LLMs;
- a replacement for Phase 2B corpus-priming evidence.

No formal power calculation is performed here (project assumptions for such
a calculation are not established for this endpoint).

## 16. Decision gate

**Replication may begin only after all of the following are true:**

1. The two configurations are **explicitly selected** and recorded
   (including exact version/thinking identifiers, or documented
   substitutions).
2. A/B/C/D **prompts are frozen** (hashes recorded).
3. Lexical **candidate-selection rules are frozen** (generator commit +
   resource pins + curation hashes).
4. The **grammar scaffold is frozen** (`scaffold_D.txt` hash; confirmed
   D≡C lexically).
5. **Source** hash and **evaluator** version/commit are frozen.
6. A **run manifest** exists listing all 24 planned cells (and optional
   expansion cells, if any).

Until then: design-only. **No runs as part of authoring this document.**
